# 装配赛正式代码

本目录是独立的真实比赛工程。复制本目录即可保留程序、配置、文档、测试、日志结构和包内运行环境；机器级的 MVS 驱动、AUBO 控制器网络、音频设备与 Windows 运行库仍须在比赛电脑上安装和核验。

当前状态：**总控软件闭环、包内真实 MVS服务和两套真实九点标定界面已实现，等待里程碑 B现场验收**。MVS客户端 5.0.2及 SDK Runtime 4.8.1.2已在当前电脑验证；真实相机序列号和三套采集参数已写入，颜色参数仍需用当前现场实拍图复核，两套九点标定尚未完成。赛前检查未全部通过时，比赛授权和运动入口保持禁用。

按当前现场决策，负载质量/重心、工具安装人工核验、真机运动总放行以及配置/代码/标定批准哈希不再进入赛前检查，也不阻断比赛授权；robot、camera、baseline通用汇总行不再重复显示。相机真实参数、两套九点、机器人实时身份/状态/TCP以及通信、标定、运动和IO异常停止仍为强制门控。blocks/trays的面积与HSV依据当前现场实拍图离线分析后直接写入`camera.json`，不再要求六色同帧批准。

吸盘`real_wiring_verified`人工核验也不再进入赛前检查或阻断授权。正式流程按最新现场确认使用工具数字输出：`TOOL_IO[1]`长期保持True使能，`TOOL_IO[0]`为True吸取、False不吸；每次写入后必须通过控制器输出回读，失败或不一致会停止流程。

光圈`real_wiring_verified`人工核验同样不再进入赛前检查或阻断授权。DO0仍固定为True开、False关，IO单步按钮和控制器输出回读保留。

“IO单步调试”页按现场确认映射提供真实按钮：标准DO0控制光圈（False关/True开），按钮会先读取DO0再切换并回读；吸盘按钮会确保`TOOL_IO[1]=True`长期使能，再将`TOOL_IO[0]`写为True吸取或False不吸并回读。该维护页独立于相机、九点、点位、TCP、Runtime和批准基线，只在独占Worker中核对唯一机器人身份、RobotMode、SafetyMode和空执行队列，并弹出真实IO确认。

唯一正式入口（Windows执行策略受限时优先双击 `.cmd`）：

```powershell
.\启动正式比赛.cmd
```

真实 MVS视觉服务必须由操作者另行明确启动，不随总控自动连接相机：

```powershell
.\启动MVS视觉服务.cmd
```

只查看相机实时画面时，先关闭占用相机的MVS视觉服务，再双击`启动MVS实时画面.cmd`。该独立窗口按`camera.json`中的唯一序列号和`blocks`参数连续取流，只显示帧号与帧率；不保存图片、不运行识别、不修改配置文件，也不连接机械臂。窗口关闭后释放相机。

“机器人现场配置”页无需填写TCP offset：当前固定使用默认法兰TCP，内部标识`flange_zero_tcp`、offset六项全零；实际回读不再为零时运动会被拒绝。页面可填写四个固定关节点，并可只读采集当前J1～J6。Block和Tray分别保存红、橙、黄、绿、蓝、紫六个独立完整TCP，共12个示教点，TCP自身Z为该色实际抓取/放置接触Z。12个基准按钮单击后立即读取并保存，不再弹出二次确认；该操作不运动、不写IO。正确顺序是“完成该场景一次九点及六色参考图 → 保持六色目标不动 → 逐色示教六个TCP”。如果现场必须先示教再走九点，程序也会保留已存TCP，但六色目标在整个九点过程中必须完全不动。拍照点或活动TCP改变时，对应六个基准仍会失效。

四个固定关节点每行提供“移动到此点”按钮。按钮只读取`config/real/motion.json`中已经保存的正式点位，弹窗显示目标六轴和实际速度比例；当前九点标定九个采样点之间保持50%，其余正式、维护和标定中心运动均为70%。操作者确认整条直达路径无人、无障碍物后，程序才连接唯一`rob1`；若`RuntimeMachine=Stopped`，所有正式及维护运动入口都会先调用`RuntimeMachine.start()`并确认变为Running，绝不调用`runProgram()`，随后执行运动并持续监视安全状态、执行队列和最终到位误差。仍强制RobotMode Running、SafetyMode Normal、空执行队列和零TCP offset。该单步不写IO，也不提供碰撞规划。

不再单独配置吸取/放置接触Z。运行时高位目标使用拍照点安全高度，垂直下降时分别使用Block红色抓取基准TCP和Tray红色放置基准TCP中保存的Z，避免两套高度数据不一致。

“相机与视觉”页可填写唯一 MVS序列号和 `task_card`、`blocks`、`trays`三套采集参数（曝光、增益、白平衡、宽高和 Offset）。blocks/trays颜色检测 ROI固定自动使用对应采集画面的完整范围 `[0, 0, Width, Height]`，无需现场填写。现场操作者勾选确认后可直接保存并人工批准，不连接相机、不要求参数回读。运行时按保存值写入 MVS节点；写入、软件触发或取图失败仍会明确停止。拍照点/TCP从机器人配置读取，标定 ID由真实九点标定生成。

双击`启动离线视觉工具.cmd`可打开独立的离线调参与批量验证窗口。它支持添加多张图片或递归导入文件夹，使用与正式比赛相同的六色HSV、形态学、面积、形状、置信度和多候选规则，查看原图、综合色掩膜和检测标注图，并在逐图/整批表格中显示通过、漏检和多候选。“编辑六色HSV范围”使用独立表格填写H/S/V上下限并支持同色多区间，确认后立即重新分析全部图片；ROI、面积或置信度输入框一经编辑就会作废旧缓存，离开输入框或按回车后自动按新值重算整批图片。参数修改只作用于内存预览；保存时生成`data/offline_vision_candidates`候选JSON，不连接MVS/机械臂，也不修改正式`camera.json`。

颜色识别拍照后会同时保存原图和带框结果图，并在“相机与视觉”、九点及自动流程监控页显示最近一次结果。绿色框表示最终选中，黄色表示多个相近合格候选，红色表示被面积、形状或置信度过滤，青色表示检测ROI；失败时也保留并显示该帧，而不是只显示“未识别到”。

同页三套参数表上方的“从当前 MVS 读取并填入上表”会按配置序列号独占连接相机，只读当前曝光、增益、三通道白平衡及采集ROI并复制到三套候选表格；不启动采集、不软件触发、不修改参数数值，也不会保存或批准。读取三通道白平衡时仅切换`BalanceRatioSelector`查看通道。使用前必须关闭MVS客户端和真实MVS视觉服务，避免相机被占用。

blocks/trays的参数处理采用离线实拍流程：在“相机与视觉”页分别点击`Block 拍照取图`和`Tray 拍照取图`，从`data/sessions`读取当前现场原图，离线计算六色HSV、面积范围和置信度并直接更新`config/real/camera.json`，随后重启MVS服务。正式装配与离线工具一致：过滤极小碎片后按面积最大选择返回目标，面积、形状、置信度和多候选只记警告。某颜色完全无目标时原位重拍一次，仍无目标则跳过该组；九点标定继续使用严格唯一方形候选规则。

同一区域另有`Block 拍照并用当前参数识别`和`Tray 拍照并用当前参数识别`两个只读诊断入口。每次只软件触发一张全新帧，并用MVS服务当前已加载的`camera.json`场景参数对同一帧识别六色，保存原图和标注图；有匹配的批准九点时同时显示工具XY及本色Δ值，没有九点时仍显示像素中心、图像角度和置信度。该入口不移动机器人、不写IO、不修改或批准配置，也不扫描旧图片兜底。

“比赛任务”页提供独立的`拍摄任务卡并发送给大模型测试`。它使用正式`task_card`采集参数拍摄一张新图，将该精确图片发送给当前环境变量配置的Qwen，并依次显示模型原始文本、解析JSON、正式识别协议封装结果及最终校验结果，同时记录模型名、请求号和耗时。测试复用正式提示词与正式校验器，但绝不写入比赛会话、生成执行令牌、连接机器人或执行返回任务；API Key不会显示或写入日志。

“维护与真实九点标定”页分别生成 blocks/trays标定。九点期间机器人携带相机在九个位置重复识别同一个固定红色目标，拟合像素变化到工具XY变化的矩阵；中心采样帧还必须同时识别红、橙、黄、绿、蓝、紫六个目标，并把各色中心像素和角度写入正式标定。进入和返回拍照中心使用70%，九个采样点之间按工具X/Y移动时保持50%。

正式定位不再把拍照TCP当作抓取基准。现场须分别把吸盘中心准确对准中心标定帧中的红色方块、红色托盘，在“机器人现场配置”页保存两个完整TCP物理基准。运行时对每种颜色计算“标定时该色相对红色的位置 + 当前该色相对自身标定原点的变化”，再叠加到对应红色物理基准；放置旋转量为托盘本色角度变化减去方块本色角度变化。缺少任一物理基准时赛前检查禁止真实抓放。

ARCS手动上电并 startup后，可先在该页点击“只读检查机械臂是否可进入标定”。绿色表示机器人身份、RobotMode、SafetyMode、执行队列和活动 TCP当前均满足维护运动门槛；九点允许`RuntimeMachine=Stopped`，不需要在ARCS运行当前加载程序。该检查不运动、不上电、不 startup、不写 IO，真正开始标定时还会重新核对。

目录原则：

- 正式程序只读取 `config/real/` 和 `calibration/real/`。
- 一台安装在机械臂末端的 MVS 相机依次承担任务卡、方块和托盘拍摄。
- 任务卡不使用九点标定；方块和托盘分别使用真实九点标定。
- 固定拍照点使用 `moveJoint`；视觉XY使用“红色物理基准TCP + 九点矩阵换算后的六色偏移”生成`poseTrans()`目标，不能使用拍照TCP代替物理基准。
- 所有固定拍照点直接 `MoveJoint`；不再做逐路线验收。每场授权前必须勾选全局直达路径安全确认，程序不提供碰撞规划。
- 任何未知身份、错误端口、非实时图像或非真实标定都会阻止比赛授权。
- 程序启动不自动连接、上电、startup、运动或写 IO。
