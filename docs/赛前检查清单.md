# 赛前检查清单

界面每项显示当前值、要求值、状态、补充方式和最后检查时间。下列关键项任何一项失败都禁止比赛授权。

## 机器与软件

- [ ] 包内 Python 3.11 x64可用。
- [ ] PySide6、AUBO SDK、OpenCV contrib、PyYAML、OpenAI客户端可导入。
- [ ] MVS Runtime、Python wrapper和相机驱动可用。
- [ ] VC++ Runtime满足厂商二进制依赖。

## 端口和身份

- [ ] AUBO真实 IP和 RPC端口正确，机器人名称/型号/序列号一致。
- [ ] 视觉端点返回 `real_mvs_vision`身份、协议版本和正确相机序列号。
- [ ] Qt监听端口没有冲突，只接受本场 session令牌。
- [ ] AI盒子地址为真实地址，返回语音服务身份和 ASR/TTS能力。
- [ ] DashScope网络、模型和密钥有效。

## 机器人安全

- [ ] RobotMode=Running。
- [ ] SafetyMode=Normal，急停和围栏状态正常。
- [ ] 执行队列空闲，RuntimeMachine状态符合配置。
- [ ] 活动 TCP名称和实际 offset逐项一致。
- [ ] 负载、重心和工具安装方向已核验。
- [ ] 机器人位于比赛待机点允许误差内。

## 点位和路径

- [ ] 待机、任务卡、方块、托盘四个关节点来自真实机器人。
- [ ] Block红色抓取点和Tray红色放置点均已保存完整TCP，且各自Z为真实接触高度。
- [ ] 当前姿态到全部固定拍照点的直接 `MoveJoint`空间内无人、无障碍物；理解程序无碰撞规划。
- [ ] 运动速度和加速度已经现场批准。

## 相机和标定

- [ ] 同一 MVS序列号与配置一致。
- [ ] `task_card`、`blocks`、`trays`三套参数已由现场操作者确认并批准。
- [ ] 当前帧请求号、时间戳和 session路径正确。
- [ ] blocks/trays各有且只有一个真实批准标定。
- [ ] 标定绑定机器人、相机、拍照点和活动 TCP。
- [ ] 两套标定最大单点误差≤0.5 mm、RMS≤0.3 mm，+X/+Y及角度四项验证通过。

## 吸盘

- [ ] 输出类型、编号、吸取/释放电平已现场确认。
- [ ] 初始状态为释放。
- [ ] 反馈输入存在且可读，或明确记录无反馈的受限策略。

## 完整性

- [ ] 代码、配置和标定哈希与批准基线一致。
- [ ] 正式运行路径不包含调试数据回退。
- [ ] 新 session目录可写，不会读取历史识别结果。
