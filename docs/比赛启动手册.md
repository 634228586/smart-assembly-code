# 比赛启动手册

## 当前重要状态

本包当前已具备正式结构、失效安全门控和包内真实 MVS视觉服务，但真实机器人、相机参数、IO、点位、标定和语音盒子尚未现场验收。赛前检查出现红项是预期行为。

当前现场版本不检查或阻断负载质量/重心、工具安装人工核验、真机运动总放行和配置/代码/标定批准哈希，也不显示robot/camera/baseline重复汇总行。相机、九点、实时机器人状态和识别失败停止仍必须通过；颜色参数由当前现场实拍图离线计算并直接写入配置。

## 启动前

1. 确认 Windows、MVS驱动、VC++ Runtime和比赛网络已就绪。
2. 确认 AUBO控制器、AI盒子和 MVS相机连接到指定网络/接口。
3. 确认机器人在比赛待机点，现场无人员处于危险区域。
4. 确认急停和围栏功能正常。
5. 确认环境变量 `DASHSCOPE_API_KEY`和 `AUBO_RPC_PASSWORD`存在。
6. 确认 `config/real`与 `calibration/real`已批准。

## 启动

现场填写 MVS参数时，可先启动总控并进入“相机与视觉”页。三套 profile分别填写曝光、增益、BalanceRatio R/G/B、Width、Height、OffsetX和 OffsetY。勾选现场确认后保存即可人工批准，不连接相机、不做参数回读。随后启动真实 MVS服务，分别使用`Block 拍照取图`和`Tray 拍照取图`采集当前现场图片；离线计算面积与HSV并直接更新`camera.json`，重启MVS服务后使用。

重启MVS服务后，可使用`Block/Tray 拍照并用当前参数识别`检查当前已保存参数。按钮每次拍一张新图并识别同一帧，显示原图/标注图和六色实际返回值；不会修改或批准参数，也不会移动机器人。相机安装在机器人末端，操作者须事先确保机器人位于对应固定拍照点。

先由操作者明确双击：

```powershell
.\启动MVS视觉服务.cmd
```

该窗口在三套参数全部填写后自动打开枚举到的第一台可用相机；正常比赛拍照只接受已人工批准 profile，并按保存值写入参数。写入、触发或取图失败会明确显示原因。保持该窗口运行，再启动总控：

```powershell
.\启动正式比赛.cmd
```

两个启动器都只使用 `.runtime`。如果缺少运行环境，先运行 `tools\构建运行环境.ps1`。总控不会自动启动相机服务。

## 正式操作

正式比赛前可在“比赛任务”页点击`拍摄任务卡并发送给大模型测试`：先确保机器人/相机已由操作者置于任务卡拍照位置，确认图片将发送到外部模型服务并可能产生费用。页面会显示本次新图、模型原始返回、解析结果和正式协议校验结果；测试不会连接机器人或执行识别出的任务。确认真实任务卡一、任务卡二均能返回合法数据后再进入正式流程。

1. 在“赛前检查”页逐项检查红/黄/绿状态。
2. TCP已固定为当前默认法兰TCP和六维全零offset，无需填写。四个关节点可逐个选中后只读保存当前J1～J6；另须保存Block六色抓取和Tray六色放置的12个完整TCP，各自Z直接作为该色接触高度。缺少任务选中颜色的对应基准时，程序会在任何运动和吸盘动作前拒绝执行。拍照点、TCP或重新九点改变时，对应场景六个基准失效。
3. 红色关键项必须全部处理；不可使用口令绕过。
4. 在 ARCS中人工完成连接后的上电和 startup确认流程。
5. 需要九点标定时，进入“维护与真实九点标定”，点击“只读检查机械臂是否可进入标定”；绿色后再继续，红色按具体原因处理。此按钮不会运动机器人。
6. 勾选普通比赛授权确认，以及“当前姿态及任务卡/方块/托盘全部直接 MoveJoint路径无人员和障碍物”全局确认，再建立本场会话。程序不做逐路线验收，也不提供碰撞规划。
7. 首次说出唤醒词“小具同学”；之后按已确认的宽松规则监听指令。
8. 识别失败时界面与语音给出原因，不运动。
9. 任务卡二合法后，在门控全绿时直接开始六组装夹；TTS失败仅黄色警告。
10. 六组完成并返航成功后才确认任务二完成。

## 结束

两张卡均完成后保存 session证据。关闭程序只清理本程序资源，不把“关闭窗口”当作急停。
