# 系统架构

## 硬件拓扑

- 一台真实 AUBO机械臂。
- 一台安装在机械臂末端、随机械臂移动的 MVS工业相机。
- 同一相机依次拍摄任务卡、方块和托盘。
- 圆形同轴吸盘；真实 IO和反馈尚未配置。
- AI语音盒子独立运行 SpeechReleaseServer。
- Qwen通过 DashScope HTTPS调用。

## 软件边界

```text
启动正式比赛.ps1
  -> 包内 Python
  -> Qt总控
      -> AUBO RPC（真实身份核验）
      -> 统一 MVS视觉服务（真实服务身份 + 相机序列号）
      -> AI语音盒子（服务身份 + ASR/TTS能力）
      -> Qwen HTTPS
```

所有端点只从 `config/real/endpoints.json`读取。连接成功不足以放行，必须再核对服务身份、协议版本和设备身份。

## 数据流

1. 机器人处于已示教的比赛待机点。
2. 操作者执行赛前检查并建立一次性比赛会话授权。
3. 机器人直达任务卡拍照点。
4. 语音触发后，MVS切换到 `task_card`配置，采集本次新图并交给 Qwen。
5. 任务一卡只记录和播报场景；任务卡二生成六组颜色计划。
6. 抓取前先拍托盘全景并缓存已识别颜色；缺色原位重拍一次。方块每组重新拍摄，连续两帧无目标则跳过该组。
7. 视觉只返回活动工具坐标系中的 `dx_tool_m/dy_tool_m`和标定后的角度。
8. 总控用 `getTcpPose() + poseTrans()`生成 Base下完整 TCP目标，不重复叠加 TCP offset。
9. 六组全部处理（成功或因目标缺失跳过）后自动返回任务卡拍照点；返航成功后才确认任务二完成，并记录成功数、跳过数及原因。

## 权限边界

- 启动程序不自动连接、上电、startup、运动或写 IO。
- 比赛授权与配置指纹绑定，硬件状态变化或配置修改立即撤销。
- 维护模式与比赛会话互斥。
- 所有真实运动只能由短时 `MotionPermit`放行，并在每条命令前重新读取安全状态。
- “机器人现场配置”的维护单点是直接SDK `MoveJoint`，允许脚本`RuntimeMachine=Stopped`；它仍要求RobotMode Running、SafetyMode Normal、空执行队列和零TCP offset。九点标定九个采样点之间保持50%，维护单点、完整比赛和九点中心运动均为70%；完整比赛与九点标定仍要求配置中的完整Runtime门控。
