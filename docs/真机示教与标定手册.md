# 真机示教与标定手册

## 总原则

维护模式与比赛会话互斥。首次工作只允许低速、单步、无吸取。程序不写 TCP和负载；它们在 ARCS中设置后由程序只读核对。

## 四个关节点

1. 在ARCS确认真实机器人身份、负载和工具方向；当前固定使用默认法兰TCP，offset六项全零，界面不再填写。
2. 拖动示教 `competition_standby`。
3. 拖动示教 `task_card_photo`，确认任务卡完整清晰。
4. 拖动示教 `blocks_photo`，确认六色方块工作区可见。
5. 拖动示教 `trays_photo`，确认六色托盘完整可见。
6. 在“机器人现场配置”表格选中对应点位，点击“读取当前机械臂关节角并直接保存到选中点位”；程序核对唯一身份、Running/Normal和空执行队列后只读采集J1～J6并原子保存，不运动，也不要求其他点位、TCP、相机或基线先完成。
7. 点位保存后，可点击该行“移动到此点”做单点核对。确认弹窗会显示目标六轴和速度比例；只有确认当前位置到目标点的整条路径无人且无障碍物后才能继续。程序复用真实运动门控并等待到位，不写IO、不提供碰撞规划。
8. 比赛运行会直接 `MoveJoint`；已取消逐路线验收，因此现场操作者仍对所有直达路径安全负责。

正式设计不使用旧的通用安全 Z或仿真过渡点，也不提供碰撞规划。每场比赛授权前，操作者必须确认当前姿态到任务卡、方块、托盘等所有直达路径内无人且无障碍物。

## 红色抓取/放置基准TCP

在相同活动TCP下，Block红、橙、黄、绿、蓝、紫各示教一个抓取TCP，Tray六色各示教一个放置TCP，共12个。每个TCP自身Z就是该色实际接触Z。必须先完成对应场景一次九点并采集六色参考图，然后保持六色目标不动，再逐色对准并只读保存TCP。拍照点、活动TCP或对应九点改变后，该场景六个基准自动失效。

## 单相机三套配置

- `task_card`：只做清晰拍照和 Qwen识别，不生成九点标定。
- `blocks`：锁定曝光/增益/白平衡/ROI/触发模式，生成 blocks真实九点标定。
- `trays`：独立锁定参数，生成 trays真实九点标定。

切换 profile后按保存值写入参数，丢弃切换前缓存帧，等待新鲜帧；不读取 MVS参数节点做一致性校验。

## blocks/trays九点现场操作

blocks和trays必须分别做一次，任务卡不做。先使用当前现场实拍图离线计算并写入该场景的HSV和面积参数，重启 MVS服务使参数生效；不要求六色同帧验证和批准。

1. 在对应工作平面摆好红、橙、黄、绿、蓝、紫六个真实目标；红色目标是九点过程唯一稳定特征，整个九点过程六个目标都不能移动。九个采样位置严格重复识别同一个红色目标，中心采样帧额外保存六色各自的中心像素与角度。
2. 确认控制器当前TCP offset仍为六项全零。程序按默认法兰坐标系执行工具X/Y变化；若现场改变TCP，旧点位、六色基准和两套九点标定全部失效。
3. 在 ARCS手动输入 PIN、上电并 startup。进入“维护与真实九点标定”，点击“只读检查机械臂是否可进入标定”。只有指示变绿才继续；红色时按显示原因处理。绿色检查不代表已运动，只代表当前身份、Running、安全状态、执行队列、Runtime和活动 TCP符合门槛。
4. 启动真实 MVS服务。分别填写 blocks/trays的 X/Y步长；填写实际直线加速度、直线速度和稳定等待时间。进入和返回拍照中心使用70%，九个采样点之间的速度比例固定50%，不能在页面改成其他比例。
5. 选择场景和目标颜色，勾选“全部直接运动路径无人且无障碍物”。点击“生成/重新生成标定”。程序会重新核对控制条件，再直接 `MoveJoint`到该场景中心拍照点，然后获取真实新帧检查目标唯一性。
6. 首次运行在每个点运动前、采样后都点击“接受当前步骤”。九点按蛇形顺序执行；任何失败、停止或重启都会废弃本套结果，下次从第1点重新开始，不静默剔除坏点。
7. 九点完成后，候选必须满足最大单点误差不超过 0.5 mm、RMS不超过 0.3 mm，并且中心帧六色基准完整，否则禁止生成正式候选。
8. 批准为最新正式标定后，旧文件归档到活动目录之外；程序会清空该场景旧六色基准，操作者必须保持新六色参考图中的目标不动并逐色重新示教。最新正式文件固定为：
   - `calibration/real/blocks/9point_blocks.json`
   - `calibration/real/trays/9point_trays.json`
9. blocks和trays必须各自保存六个完整同色基准TCP；12个按钮只读当前完整TCP，不拍照、不运动、不写IO。基准TCP中的Z直接作为该色实际接触高度。
10. 最新批准文件绑定真实机器人、拍照点、活动 TCP、分辨率、步长和六色视觉原点。拍照点或TCP改变会使对应物理基准自动变为`UNSET`；九点批准本身不再清除按本流程预先保存的基准。

正式换算为：`目标TCP_XY = 红色物理基准TCP_XY + 九点映射(当前本色中心 - 标定红色中心)`。该式等价于“标定时本色相对红色的偏移 + 当前本色相对自身标定原点的变化”。旋转修正为`托盘本色ΔR - 方块本色ΔR`。

原始帧、标注帧、帧号、时间、实际 TCP、像素坐标和残差均保存在标定 session证据目录。标定页面不会上电、startup或写 IO；开始前控制器必须已由操作者置于允许状态。

## 逐级放行

`只读身份 → 低速单点 → 单条高位XY → 垂直下降/返回无IO → IO单测 → 单组 → 六组 → 双任务卡全流程`

每一级失败立即停止，不自动进入下一级。

## DO0光圈与工具IO吸盘单步测试

现场已确认控制映射：标准DO0为光圈，False关闭、True打开；吸盘使用`TOOL_IO[1]`长期True使能，`TOOL_IO[0]`为True吸取、False不吸。进入“IO单步调试”页前，仍须由操作者在ARCS手动上电并startup。

光圈按钮读取标准DO0后写入相反电平并回读。吸盘按钮先检查TOOL_IO[0]/[1]为输出模式，确保TOOL_IO[1]=True，再写TOOL_IO[0]并回读；停止吸取时TOOL_IO[1]仍保持True。手动IO不要求相机、九点、点位、TCP、RuntimeMachine或批准基线通过，不运动、不自动上电、不startup。
